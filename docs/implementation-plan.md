# 屏幕视觉驱动的游戏界面自动化：实现方案

> 本文描述一个仅通过屏幕画面识别和系统级键鼠事件工作的桌面自动化原型。它不读取或修改游戏内存、不注入进程、不拦截网络数据，也不包含反检测、规避风控或绕过账号安全验证的功能。
>
> 在线游戏自动化可能违反游戏服务条款并影响其他玩家。开发、验证与演示应限定在获得明确授权的环境中，例如本地模拟界面、训练场或自定义房间；遇到未知界面、验证弹窗、断线或异常时必须停止并交由人工处理。

## 1. 目标与范围

项目目标是实现一个基于屏幕捕捉、视觉识别和键盘鼠标控制的有限状态机（FSM）原型，能够在受控测试环境中完成以下流程：

1. 在主界面选择预设的快速模式并发起匹配。
2. 进入英雄选择界面后选择预配置英雄。
3. 游戏开始后执行有限、可中断的移动序列，避免长时间停留在出生区域。
4. 结算后识别结果并回到可开始下一轮的界面。
5. 只在明确识别到胜利时累加计数；达到 50 胜后停止新一轮操作并安全退出。

### 非目标

- 不读取、修改或扫描进程内存。
- 不使用 DLL 注入、驱动注入、网络封包修改、反检测或规避封禁手段。
- 不自动处置验证码、双因素验证、账号安全提示、更新提示或支付界面。
- 不以排位或公共匹配环境作为测试目标。
- 不实现根据对局内容做战术、瞄准、攻击或对抗决策的功能。

## 2. 总体架构

```text
┌──────────────┐
│ 屏幕/窗口捕捉 │
└──────┬───────┘
       ▼
┌──────────────┐
│ 图像预处理    │  裁剪、缩放、颜色/对比度校正
└──────┬───────┘
       ▼
┌──────────────┐
│ 视觉识别      │  模板匹配、OCR、场景分类、置信度
└──────┬───────┘
       ▼
┌──────────────┐
│ 有限状态机    │  状态转换、超时、重试、异常分流
└──────┬───────┘
       ▼
┌──────────────┐
│ 输入执行器    │  系统级鼠标/键盘、按键释放、急停
└──────┬───────┘
       ▼
┌──────────────┐
│ 状态与日志    │  计数持久化、截图、审计、告警
└──────────────┘
```

设计原则：视觉识别决定是否执行动作，固定坐标和固定延时只可作为辅助；任何低置信度、超时或未知画面都优先停止，而不是继续盲目输入。

## 3. 模块设计

### 3.1 窗口与屏幕捕捉

- 捕捉指定游戏窗口或配置好的屏幕区域，不依赖进程内数据。
- 启动时校验窗口标题、尺寸、分辨率和 UI 缩放是否匹配配置。
- 统一输出 RGB 图像帧、采集时间和窗口坐标，供识别与日志模块使用。
- 窗口失焦、最小化或尺寸变化时暂停状态机并释放全部按键。

### 3.2 视觉识别

采用组合识别，所有结果均携带 `label`、`confidence`、`timestamp` 和可选 `bbox`：

| 识别对象 | 建议方式 | 作用 |
| --- | --- | --- |
| 主菜单、模式入口、确认按钮 | 多尺度模板匹配 | 判断是否可启动流程 |
| 模式名称、结算文字、错误提示 | OCR + 关键词校验 | 区分快速模式、胜利、失败和异常 |
| 英雄头像、确认区域 | 模板匹配 | 仅选择配置允许的英雄 |
| 出生区域/正常对局/结算画面 | 轻量场景分类或多模板投票 | 驱动状态转换 |
| UI 弹窗、断线、更新、验证 | 模板与 OCR | 转入人工处理状态 |

建议做法：

- 为每种支持的分辨率和语言分别维护模板集。
- 每次关键状态转换要求连续多帧识别一致，避免单帧误判。
- 设定置信度阈值；低于阈值时记录截图并进入 `UNKNOWN_SCREEN`。
- 将截图样本、模板版本和识别结果关联记录，便于回归测试。

### 3.3 输入执行器

- 使用操作系统提供的普通键盘鼠标事件接口，例如 Windows 的 `SendInput`。
- 对每个动作提供最大时长、冷却时间和成功条件，不允许无限按键或连点。
- 所有异常路径均调用 `release_all_keys()`。
- 提供全局紧急停止键（例如 `F12`）及鼠标移动至预设角落时停止。
- 输入模块只接受状态机发出的结构化动作，不直接执行自由文本或任意脚本指令。

### 3.4 状态持久化与可观测性

使用 SQLite 或 JSON 保存最小状态：

```json
{
  "wins": 0,
  "current_state": "MAIN_MENU",
  "last_match_result": null,
  "last_transition_at": "2026-08-13T00:00:00Z",
  "consecutive_failures": 0,
  "template_set_version": "v1"
}
```

日志至少包含：状态转移、识别置信度、输入动作、超时、错误原因和关键截图路径。胜场只在结算页明确识别到胜利关键词、且该结算尚未处理时递增。

## 4. 有限状态机

### 4.1 状态列表

| 状态 | 进入条件 | 允许动作 | 成功出口 | 失败出口 |
| --- | --- | --- | --- | --- |
| `INIT` | 程序启动 | 加载配置、校验窗口、恢复存档 | `MAIN_MENU` | `MANUAL_INTERVENTION` |
| `MAIN_MENU` | 主界面高置信度识别 | 打开模式页面 | `MODE_SELECT` | `UNKNOWN_SCREEN` |
| `MODE_SELECT` | 模式页面已识别 | 选择预设模式、确认 | `QUEUE_REQUESTED` | `MANUAL_INTERVENTION` |
| `QUEUE_REQUESTED` | 已请求匹配 | 只监测画面，不重复点击 | `MATCH_FOUND` | `QUEUE_TIMEOUT` |
| `MATCH_FOUND` | 已确认进入对局 | 等待英雄选择 | `HERO_SELECT` | `UNKNOWN_SCREEN` |
| `HERO_SELECT` | 英雄选择 UI 已识别 | 选择预配置英雄、确认 | `SPAWN_ROOM` | `MANUAL_INTERVENTION` |
| `SPAWN_ROOM` | 出生区域 UI 已识别 | 执行短时移动序列 | `ACTIVE_GAME` | `MOVEMENT_TIMEOUT` |
| `ACTIVE_GAME` | 正常对局画面已识别 | 仅做有限、可中断的保活移动 | `POST_GAME` | `UNKNOWN_SCREEN` |
| `POST_GAME` | 结算或离开对局 UI 已识别 | 判断结果、返回可排队界面 | `RESULT_CONFIRMED` | `MANUAL_INTERVENTION` |
| `RESULT_CONFIRMED` | 胜/负结果已确认 | 更新持久化统计 | `MAIN_MENU` 或 `SAFE_EXIT` | `UNKNOWN_SCREEN` |
| `SAFE_EXIT` | 胜场达到 50 或用户终止 | 释放按键、停止新动作、写日志 | `STOPPED` | 无 |
| `UNKNOWN_SCREEN` | 无法可靠判断当前画面 | 释放按键、截图、告警 | 人工恢复后重新识别 | `STOPPED` |
| `MANUAL_INTERVENTION` | 验证、更新、账号/网络异常 | 释放按键、截图、告警 | 人工恢复后重新识别 | `STOPPED` |

### 4.2 主要流程

```text
INIT → MAIN_MENU → MODE_SELECT → QUEUE_REQUESTED
                                      │
                                      ▼
                                MATCH_FOUND
                                      │
                                      ▼
                                 HERO_SELECT
                                      │
                                      ▼
                                  SPAWN_ROOM
                                      │
                                      ▼
                                  ACTIVE_GAME
                                      │
                                      ▼
                                   POST_GAME
                                      │
                                      ▼
                              RESULT_CONFIRMED
                              ├─ wins < 50 ─→ MAIN_MENU
                              └─ wins ≥ 50 ─→ SAFE_EXIT → STOPPED
```

任一状态出现窗口失焦、低置信度、超时、断线、更新、验证或无法归类的弹窗时，都应释放按键并转入 `UNKNOWN_SCREEN` 或 `MANUAL_INTERVENTION`。

## 5. 关键流程细化

### 5.1 发起匹配

1. 连续多帧确认主菜单存在。
2. 点击模式入口，等待模式页面出现。
3. 用文字和模板共同确认目标模式；若不一致则停止。
4. 点击确认并确认等待中状态出现。
5. 在配置的最大等待时间内只观察状态变化；不反复点击。
6. 超时、网络提示或界面不符时暂停并保存截图。

### 5.2 选择英雄

1. 确认英雄选择界面与倒计时存在。
2. 在允许英雄列表中寻找匹配模板。
3. 点击英雄并确认选择状态，而不是仅依赖点击成功。
4. 英雄不可用、角色冲突、倒计时过短或识别不可靠时交给人工。

配置示例：

```yaml
hero:
  allowed:
    - "hero_a"
  min_select_time_seconds: 8
  confidence_threshold: 0.92
```

### 5.3 出生区域与有限移动

此模块的目标仅是让测试状态机验证“已离开出生区域”和“输入可以随时停止”，不是进行游戏决策。

1. 确认已经进入可控制状态。
2. 执行长度受限的预设输入片段，例如短时前进、短时转向、释放按键。
3. 每个片段结束后重新捕捉并判断画面是否已进入正常区域。
4. 达到最大动作次数或时间仍无法确认时停止并人工检查。
5. 游戏结束、死亡、暂停、菜单、失焦或未知画面一经识别，立即释放所有按键。

不要实现无限循环、无上限随机输入或针对其他玩家的行为决策。

### 5.4 结算、计数与停止

1. 识别结算 UI，并连续多帧确认胜利或失败结果。
2. 为该场结算生成唯一标记，确保重绘或延迟不会重复计数。
3. 仅在确认胜利时执行 `wins += 1` 并立即持久化。
4. `wins < 50`：返回主菜单后再次进入流程。
5. `wins >= 50`：进入 `SAFE_EXIT`，释放输入、停止新匹配、保存最终日志；可按配置返回主菜单或关闭应用。

## 6. 配置、阈值与错误恢复

建议集中在 `config.yaml` 管理以下项目：

```yaml
window:
  expected_resolution: [1920, 1080]
  require_focus: true

recognition:
  default_confidence_threshold: 0.90
  required_consecutive_frames: 3
  capture_interval_ms: 300

timeouts:
  queue_seconds: 900
  hero_select_seconds: 20
  spawn_movement_seconds: 30
  active_game_seconds: 1800
  post_game_seconds: 120

safety:
  emergency_stop_key: "F12"
  max_consecutive_failures: 3
  stop_on_unknown_screen: true
  stop_on_focus_loss: true

session:
  target_wins: 50
  exit_action: "return_to_menu"
```

恢复原则：

- 页面未识别：先释放输入、截屏、记录原因，然后停止等待人工确认。
- 单次动作未确认：在严格次数限制内重新识别；不可盲目重复输入。
- 网络、验证、更新、账号安全等提示：不自动处置。
- 程序崩溃后：从持久化状态恢复，但必须重新检测屏幕状态，不能假定原状态仍然成立。

## 8. 开发里程碑

### M0：边界与样本

- 固化授权测试环境和安全停止约定。
- 收集支持分辨率、语言和 UI 主题下的去敏截图样本。
- 定义状态标签、截图命名规则和模板版本策略。

验收：人工可标注每张样本属于一个明确状态或异常状态。

### M1：只读视觉原型

- 实现窗口定位、周期捕捉和画面存档。
- 完成主菜单、英雄选择、出生区域、对局、结算和异常画面的离线识别。
- 输出状态、置信度与标注框，但不发送任何输入。

验收：在录制截图/视频回放中稳定输出状态；低置信度必须标为未知。

### M2：输入安全层

- 实现受限动作 API、按键生命周期管理和 `release_all_keys()`。
- 接入全局急停、焦点检查、动作上限及操作审计。
- 在非游戏窗口或模拟窗口中测试。

验收：急停和失焦后不残留任意按键按下状态。

### M3：状态机与模拟流程

- 在模拟界面或录制回放驱动下实现完整状态转换。
- 补齐所有状态的超时与异常分流。
- 加入可恢复的本地持久化。

验收：正常、超时、断线、未知画面和重启恢复场景均有可预测的停止或恢复结果。

### M4：受控环境集成验证

- 只在明确授权的自定义/训练环境验证菜单、选择和有限移动动作。
- 每次运行限制局数、总时长和失败次数。
- 人工审阅日志、截图和计数正确性。

验收：不发生连续盲操作；所有异常均停止并保留证据。

### M5：统计与交付

- 验证胜利计数去重、崩溃恢复和 50 胜停止条件。
- 编写运行说明、配置说明、故障排除和测试报告。
- 默认配置保持“未知即停止”，而非自动重试。

验收：达到目标胜场时，无新输入、无新匹配，且最终状态和日志均已写入磁盘。

## 9. 测试策略

1. **视觉单元测试**：为每个状态准备正样本、负样本、模糊/遮挡样本和不同分辨率样本。
2. **状态机测试**：用伪造识别事件验证合法转换、非法转换、超时与重启恢复。
3. **输入安全测试**：验证每条异常路径都调用按键释放；验证急停在动作执行中生效。
4. **回放测试**：用录制的视频帧离线运行，复现识别和状态转移问题，不需要操作真实界面。
5. **受控集成测试**：只在获授权的环境中进行，默认人工监视，逐步增加运行时间。

核心指标：状态识别准确率、关键状态的误判率、未知画面停止率、按键残留次数（应为 0）、胜利重复计数次数（应为 0）和异常恢复成功率。

## 10. 发布前检查清单

- [ ] 所有动作都由明确的视觉状态触发。
- [ ] 关键状态转换至少由多帧和置信度阈值确认。
- [ ] 未知画面、窗口失焦、断线、验证和更新均会释放按键并停止。
- [ ] 计数只在确认胜利且未处理过的结算中递增。
- [ ] 达到 50 胜后不会发起新的匹配或输入。
- [ ] 急停可随时使用，并经过实际测试。
- [ ] 不含内存访问、注入、网络篡改或规避检测代码。
- [ ] 使用范围、测试环境和服务条款风险已在 README 和运行文档中说明。
